<objective>
Fix a confirmed bug where room.svelte.ts reads `ws.reconnectAttempts` — a property that does not exist on PartySocket (the correct property is `retryCount`). Because the bug makes the guard read `undefined > 0 === false`, every reconnected client falls into the first-connect branch and resends `hello` instead of `syncRequest`. That breaks post-reconnect sync and, depending on server interpretation, can confuse host-tracking during UAT.

Also add two temporary diagnostic `console.log` statements to support the in-progress host-failover manual UAT:
1. Server-side in `party/game-room.ts` `#promoteNextHost` so we see when/if the DO attempts promotion and who it picks.
2. Client-side in `src/lib/stores/room.svelte.ts` `hostChanged` handler so we see whether the browser actually received the promotion.

Purpose: unblock Phase 5 host-failover UAT by fixing the reconnect guard and giving us visible telemetry while the feature is still being verified.
