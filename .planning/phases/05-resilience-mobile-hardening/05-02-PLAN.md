<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| server → client syncResponse | Client trusts server-provided state; board data replaces local state atomically |
| client → server syncRequest | No user-supplied payload; safe by design |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-5-06 | Information Disclosure | syncResponse board field | mitigate | Board data is sent by the server only to the requesting connection (unicast in Plan 01). Client-side: the syncResponse handler only stores the board locally — it does not re-broadcast or log it. |
| T-5-07 | Spoofing | ws.reconnectAttempts check | accept | The reconnect detection (ws.reconnectAttempts > 0) determines whether to send hello or syncRequest — no security boundary. Even if a first-connect sends syncRequest instead of hello, the server's syncRequest handler sends a snapshot of whatever state exists (possibly empty), which is harmless. |
| T-5-08 | Denial of Service | visibilitychange listener accumulation | mitigate | Listener is registered once per store instance and removed in disconnect(). Page component calls disconnect() in onDestroy (Phase 4 pattern). Play-again flow navigates to same route — SvelteKit remounts the component, triggering onDestroy → disconnect() first. Pitfall 5 addressed. |
</threat_model>
