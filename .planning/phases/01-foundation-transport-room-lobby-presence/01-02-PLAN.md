**Review Feedback Addressed (from 01-REVIEWS.md):**
- **HIGH — Room existence semantics fragile with DOs:** Persistent `initialized: boolean` flag written ONLY on first successful `hello`. `/exists` and `onBeforeConnect` read the flag without writing — they can NEVER create or revive a room. Explicit test (`game-room-existence.test.ts`) proves `/exists` against a never-created code returns 404 AND a subsequent WS upgrade to the same code still returns 404.
- **HIGH — WS upgrade 404 behavior:** `onBeforeConnect` returns a `Response` with status 404 BEFORE PartyServer performs the WebSocket upgrade. Test asserts upgrade FAILS (client receives 404 HTTP, no `open` event), not "accepted then closed".
- **MEDIUM — Host assignment under reconnect/duplicate sessions:** Presence tracked by `playerId`, not `conn.id`. `#connectionsByPlayerId: Map<string, Set<string>>` tracks all open sockets per player. Second `hello` with same playerId is treated as update/reconnect (does not duplicate player). Host assignment uses `#initialized && #hostId === null` guard — second-tab host does not overwrite existing hostId.
- **MEDIUM — Presence leave noisy with multiple connections:** `playerLeft` is broadcast ONLY when the LAST socket for a playerId closes (`connections.size === 0` after delete). Closing one of two tabs does NOT broadcast.
- **MEDIUM — Server-side display name sanitization:** Server re-validates `displayName` via the shared `DisplayName` Valibot schema (with `v.trim()`) from Plan 01 on every `hello`. Oversized, empty, or whitespace-only names → `{type:"error",code:"invalid_display_name"}`.
- **MEDIUM — Invalid message handling specified:** Schema parse failure → `{type:"error",code:"bad_message"}` sent to offender; connection stays open (no oracle). Unit test asserts this.

Output: A backend that, against `wrangler dev`, satisfies SESS-01, SESS-05 (broadcast), SESS-06 (host), and SESS-07 (404) — testable without any UI.
